# EdgeXI: تحليل مباريات كرة القدم يومياً بنموذج إحصائي + محلل بالذكاء الاصطناعي (Claude أو ChatGPT أو Gemini)

تطبيق كامل (Next.js 14 + shadcn/ui + PostgreSQL) يعمل كل يوم وحده في السحابة:

1. يحمّل نتائج الموسمين الأخيرين وأودز المباريات القادمة من **football-data.co.uk** (مجاني، بلا مفتاح).
2. يدرّب نموذج **Dixon-Coles** للأهداف، ونموذج **Negative Binomial** للركنيات، لكل دوري.
3. يحسب احتمال كل سوق: 1X2، فرصة مزدوجة، Draw no bet، أكثر/أقل من 1.5 و2.5 و3.5، كلا الفريقين يسجل، أهداف كل فريق، الركنيات.
4. يقارن احتمال النموذج مع احتمال الأودز بعد حذف هامش الشركة، ولا يحتفظ إلا بالرهانات التي لها **قيمة** (edge).
5. يحسب المبلغ بطريقة **Kelly الجزئية** مع حد أقصى لكل رهان.
6. يرسل كل رهان إلى **المحلل الذكي** الذي تختاره في الإعدادات (**Claude** أو **ChatGPT** أو **Gemini**)، فيبحث في الويب عن الإصابات والإيقافات والتشكيلة، ثم يحكم: KEEP / CAUTION (يُقسم المبلغ على 2) / AVOID (المبلغ = 0).
7. المحلل يكتب ملخص اليوم باللغة التي تختارها (العربية، الدارجة، الفرنسية، الإنجليزية).
8. في اليوم التالي يسجّل النتائج تلقائياً، ويحسب الربح والخسارة و**CLV** (هل أخذت أودز أفضل من أودز الإغلاق؟).

> المحلل الذكي لا يخترع الاحتمالات. الأرقام تأتي من النموذج الإحصائي، والمحلل يراجع ما لا يراه النموذج (الأخبار).

اللوحة خاصة: لا يدخلها إلا من سجّل الدخول ببريد موجود في `ALLOWED_EMAILS` (راجع [تسجيل الدخول](#تسجيل-الدخول)).

الواجهة بالعربية (من اليمين إلى اليسار) أو بالإنجليزية. زر **العربية / English** في القائمة الجانبية وفي الإعدادات، والاختيار يُحفظ في cookie اسمه `locale` (الافتراضي العربية).

## الصفحات

| الصفحة | المحتوى |
|---|---|
| Dashboard | رأس المال، الرهانات المفتوحة، الربح المتوقع، ROI، ملخص المحلل الذكي، آخر التشغيلات، زر "Run analysis now" |
| Picks | رهانات اليوم والأيام القادمة، مع زر Place / Skip |
| Matches | كل المباريات التي حللها النموذج، مع احتمالات 1X2 وxG و Over 2.5 و BTTS |
| Match | صفحة المباراة: الرهان المقترح، كل الأسواق، أكثر النتائج احتمالاً، قوة الفريقين، حاسبة لأودز شركتك، تحليل المحلل الذكي مع المصادر |
| Bet slip | ورقة اليوم: المبلغ الكلي، عدد الرهانات المتوقع أن تربح، احتمال أن يربح واحد على الأقل، ولماذا لا تجمعها في كومبيني |
| Performance | منحنى الربح، ROI، نسبة الفوز، CLV، Brier score، جدول الرهانات المنتهية. وضعان: كل الاقتراحات (paper) أو ما راهنت عليه فعلاً |
| Settings | رأس المال، Kelly، الحد الأقصى، الحد الأدنى للقيمة والاحتمال والأودز، الدوريات، المحلل الذكي (المزوّد والنموذج)، لغة التحليل، البحث في الويب، لغة الواجهة، والأمان (تغيير كلمة السر، الجلسات النشطة، الأشخاص الذين لهم حق الدخول) |
| Login (`/login`) | البريد الإلكتروني وكلمة السر. في أول تشغيل: "Create your account" |

## التشغيل على جهازك

المطلوب: Node.js 20 أو أحدث، وقاعدة PostgreSQL.

```bash
npm install
cp .env.example .env        # ضع DATABASE_URL ومفتاح المزوّد الذي تختاره (ANTHROPIC_API_KEY أو OPENAI_API_KEY أو GEMINI_API_KEY)
                            # وبريدك في ALLOWED_EMAILS، وBETTER_AUTH_SECRET (openssl rand -base64 32)
npm run db:push             # ينشئ الجداول (ومعها جداول تسجيل الدخول auth_*)
npm run seed:demo           # اختياري: بيانات اصطناعية لتجربة الواجهة بلا إنترنت
npm run dev                 # http://localhost:3000 ← يفتح /login: أنشئ حسابك ببريد من ALLOWED_EMAILS
```

لتشغيل التحليل الحقيقي يدوياً: `npm run job:daily` أو زر **Run analysis now** في الـ Dashboard.

> `seed:demo` يمسح الجداول ويضع دوري وهمياً. قبل الاستعمال الحقيقي شغّل `npm run db:push` على قاعدة نظيفة أو امسح الجداول.

## النشر في السحابة (مجاني تقريباً)

### 1. قاعدة البيانات: Neon
- أنشئ حساباً على neon.tech، ثم مشروعاً جديداً، وانسخ رابط الاتصال (Connection string).
- على جهازك: ضعه في `.env` كـ `DATABASE_URL` ثم `npm run db:push`.

### 2. مفتاح المحلل الذكي
اختر المزوّد في **Settings ← المحلل الذكي**، وضع مفتاحه في متغيرات البيئة. يكفي مفتاح المزوّد المختار فقط. المفاتيح تبقى في الخادم ولا تُرسل إلى المتصفح أبداً: الإعدادات تعرض فقط "المفتاح مضبوط" أو "المفتاح غير موجود".

| المزوّد | المفتاح | من أين | النموذج الافتراضي | لتغيير الافتراضي | البحث في الويب |
|---|---|---|---|---|---|
| Claude | `ANTHROPIC_API_KEY` | console.anthropic.com ← API Keys | `claude-sonnet-5-5` | `CLAUDE_MODEL` (مثلاً `claude-haiku-5-5` أرخص، `claude-opus-5-5` أقوى) | أداة `web_search` |
| ChatGPT | `OPENAI_API_KEY` | platform.openai.com/api-keys | `gpt-5.5` | `OPENAI_MODEL` | أداة `web_search` في Responses API |
| Gemini | `GEMINI_API_KEY` | aistudio.google.com/apikey | `gemini-flash-latest` | `GEMINI_MODEL` | Google Search grounding |

- يمكنك أيضاً كتابة نموذج آخر في خانة **النموذج** في الإعدادات (اتركها فارغة لاستعمال الافتراضي).
- كل المزوّدين يأخذون نفس التعليمات ويرجعون نفس الصيغة، والمراجعة تحفظ اسم المزوّد والنموذج (مثلاً `openai/gpt-5.5`).
- إذا لم يكن مفتاح المزوّد المختار موجوداً، تُحفظ الرهانات بدون مراجعة (كما كان الحال بدون `ANTHROPIC_API_KEY`).
- التكلفة: مراجعة واحدة مع بحث ويب لكل رهان (حد أقصى 8 في اليوم افتراضياً) + ملخص واحد. راقب الاستهلاك في لوحة المزوّد.

### 3. الواجهة: Vercel
- ارفع المشروع إلى GitHub، ثم في vercel.com ← Add New Project ← اختر المستودع.
- في Environment Variables أضف: `DATABASE_URL`، مفتاح المزوّد المختار (`ANTHROPIC_API_KEY` أو `OPENAI_API_KEY` أو `GEMINI_API_KEY`)، `CRON_SECRET` (نص عشوائي طويل)، ومتغيرات تسجيل الدخول:
  - `ALLOWED_EMAILS`: البريد المسموح له بالدخول، مفصول بفواصل (مثلاً `you@gmail.com,friend@gmail.com`). بدونه لا يستطيع أحد الدخول.
  - `BETTER_AUTH_SECRET`: نص عشوائي طويل (`openssl rand -base64 32`). **إجباري**: بدونه ترفض صفحة الدخول العمل في الإنتاج. إذا غيّرته، تُغلق كل الجلسات.
  - `BETTER_AUTH_URL` (اختياري، في بيئة Production فقط): رابط موقعك، مثلاً `https://edgexi.vercel.app`. إذا تركته فارغاً يُؤخذ من كل طلب، وهذا يعمل أيضاً مع روابط Preview.
- بعد النشر افتح الموقع: يحوّلك إلى `/login`، وفيه "Create your account" لأن القاعدة لا تحتوي أي حساب بعد. أنشئ حسابك فوراً.
- `vercel.json` فيه Cron يشغّل `/api/cron/daily` كل يوم على 07:00 UTC.

### 4. التشغيل اليومي (اختر واحداً)
- **Vercel Cron**: يعمل وحده بعد النشر. حد مدة الدالة 300 ثانية، وهذا يكفي غالباً لـ 8 رهانات.
- **GitHub Actions** (أكثر أماناً إذا كان التحليل طويلاً): الملف `.github/workflows/daily.yml` جاهز. في GitHub ← Settings ← Secrets and variables ← Actions أضف `DATABASE_URL` ومفتاح المزوّد المختار (`ANTHROPIC_API_KEY` أو `OPENAI_API_KEY` أو `GEMINI_API_KEY`) كـ Secrets، ويمكنك إضافة `CLAUDE_MODEL` / `OPENAI_MODEL` / `GEMINI_MODEL` كـ Variables. يمكنك تشغيله يدوياً من تبويب Actions. إذا استعملت هذا، احذف `crons` من `vercel.json` حتى لا يعمل مرتين.
- GitHub Actions يتصل بقاعدة البيانات مباشرة ولا يمر بالموقع، فتسجيل الدخول لا يؤثر عليه: لا يحتاج `ALLOWED_EMAILS` ولا `BETTER_AUTH_SECRET`. أما Vercel Cron فيستدعي `/api/cron/daily`، وهذا المسار خارج تسجيل الدخول ومحمي بـ `CRON_SECRET` كما كان.

## تسجيل الدخول

تسجيل الدخول بالبريد الإلكتروني وكلمة السر عبر [Better Auth](https://www.better-auth.com)، والحسابات والجلسات محفوظة في نفس قاعدة PostgreSQL (جداول `auth_users` و`auth_sessions` و`auth_accounts` و`auth_verifications` و`auth_rate_limits`). لا توجد خدمة خارجية ولا تسجيل بحساب Google أو غيره.

- **من يدخل**: فقط البريد الموجود في `ALLOWED_EMAILS` (لا يهم الحرف الكبير أو الصغير). الخادم يرفض إنشاء حساب أو تسجيل دخول أي بريد آخر برسالة "This email is not allowed"، والواجهة تعرض فقط جواب الخادم.
- **أول تشغيل**: ما دامت القاعدة لا تحتوي أي حساب، تعرض `/login` استمارة "Create your account". بعد إنشاء أول حساب يُغلق التسجيل نهائياً (في الخادم أيضاً).
- **إضافة شخص آخر**: أضف بريده إلى `ALLOWED_EMAILS` (وأعد النشر في Vercel)، ثم في **Settings ← الأمان ← إضافة شخص** أنشئ حسابه بكلمة سر مؤقتة وأعطها له، ويغيّرها هو من نفس الصفحة بعد الدخول.
- **سحب الدخول من شخص**: احذف بريده من `ALLOWED_EMAILS` وأعد النشر. جلساته المفتوحة تتوقف فوراً، ولا يستطيع الدخول من جديد.
- **كل صفحة وكل API** تحتاج جلسة صالحة، ما عدا `/login` و`/api/auth/*` و`/api/cron/*`. الصفحات تحوّل إلى `/login?next=...`، والـ API يرجع 401. المسارات التي تغيّر البيانات تتحقق من الجلسة مرة ثانية بنفسها.
- **الحماية**: 5 محاولات دخول كل 5 دقائق لكل عنوان IP (بعدها "Too many attempts")، وcookie الجلسة `HttpOnly` و`SameSite=Lax` و`Secure` في الإنتاج، والجلسة تدوم 7 أيام وتتجدد مع الاستعمال. رسالة الخطأ واحدة سواء كان البريد بلا حساب أو كلمة السر خاطئة.
- **الأمان في Settings**: تغيير كلمة السر (يُخرج الأجهزة الأخرى)، قائمة الجلسات النشطة، وزر "Sign out other sessions".
- **نسيت كلمة السر؟** لا يوجد بريد لاسترجاعها (لا توجد خدمة بريد). احذف حسابك من قاعدة البيانات (في Neon ← SQL Editor):
  ```sql
  delete from auth_users where email = 'you@example.com';
  ```
  إذا لم يبق أي حساب، تعود استمارة "Create your account" في `/login`. وإذا بقي حساب آخر، يضيفك صاحبه من **إضافة شخص**.

## اختبار النموذج قبل المال الحقيقي

```bash
npm run test:model            # اختبارات الرياضيات على دوري اصطناعي
npm run backtest -- E0 2425   # Backtest على الدوري الإنجليزي موسم 2024/25 ببيانات حقيقية
```

الـ Backtest يعيد تدريب النموذج كل أسبوع بالمباريات السابقة فقط، ويطبع:
- **Brier score**: هل الاحتمالات معايرة؟ حوالي 0.60 = مستوى الشركات، 0.667 = عشوائي.
- **ROI** برهان ثابت.
- **متوسط CLV**: أهم رقم. إذا كان سالباً باستمرار، فالنموذج لا يتفوق على السوق.

**النصيحة**: اترك التطبيق يعمل شهرين أو ثلاثة في وضع paper (لا تضغط Place)، وراقب صفحة Performance. إذا لم يكن CLV موجباً على 200 رهان أو أكثر، فلا تراهن بمال حقيقي.

## الإعدادات المهمة

| الإعداد | الافتراضي | المعنى |
|---|---|---|
| Kelly fraction | 0.25 | ربع Kelly. لا ترفعه. |
| Max stake per bet | 2% | حد أقصى من رأس المال لكل رهان |
| Minimum edge | 4% | احتمال × أودز − 1 |
| Minimum probability | 30% | لا رهانات على احتمالات ضعيفة |
| Odds | 1.40 إلى 4.50 | |
| Model weight | 0.5 | يخلط احتمال النموذج مع احتمال السوق بالنصف. السوق قوي جداً، ولهذا لا نعتمد على النموذج وحده. |

## حدود يجب أن تعرفها

- **مصدر البيانات**: football-data.co.uk يغطي الدوريات الأوروبية الكبرى (الإنجليزي، الإسباني، الإيطالي، الألماني، الفرنسي، الهولندي، البرتغالي، البلجيكي، التركي، الأسكتلندي، اليوناني). **البطولة المغربية غير موجودة.** ملف `fixtures.csv` يُحدَّث عادة مرتين في الأسبوع (قبل نهاية الأسبوع وقبل منتصف الأسبوع)، فقد تكون الأودز أقدم من أودز شركتك.
- **الأودز**: التطبيق يستعمل متوسط السوق (Avg). أودز 1xBet وغيرها قد تختلف. استعمل حاسبة "Check your bookmaker's odds" في صفحة المباراة قبل كل رهان.
- **الركنيات وBTTS**: لا توجد لها أودز في المصدر المجاني، فلا تصير picks تلقائية. احتمالاتها موجودة في صفحة المباراة، والحاسبة تقول لك هل أودز شركتك فيها قيمة.
- **لا يوجد نموذج يضمن الربح.** الشركات تأخذ هامشاً بين 5 و8%، وتقلّص حدود من يربح باستمرار. أفضل نتيجة واقعية هي ربح صغير على مئات الرهانات، والنتيجة الأكثر شيوعاً قريبة من التعادل أو خسارة صغيرة.

## شعارات الفرق والدوريات

- المصدر الافتراضي **TheSportsDB** (مجاني، المفتاح العام `123`، حوالي 30 طلباً في الدقيقة). إذا وضعت `API_FOOTBALL_KEY` يستعمل التطبيق **API-Football** بدلاً منه (الخطة المجانية 100 طلب في اليوم، فقد يكتمل الملء في يومين).
- الشعارات محفوظة في جدولي `team_logos` و`league_logos`، وتُنشأ وحدها عند أول طلب. الفريق الذي لم يوجد له شعار يُحفظ بقيمة فارغة ولا يُبحث عنه من جديد قبل 30 يوماً، وتظهر مكانه الحروف الأولى الملونة.
- التشغيل اليومي يبحث فقط عن الفرق غير الموجودة في الجدول (90 ثانية كحد أقصى)، وخطأ في الشعارات لا يوقف التحليل.
- لملء كل فرق الدوريات المفعّلة مرة واحدة: `npm run logos:sync`. يطبع عدد الفرق التي لها شعار في كل دوري، والفرق الناقصة.
- أسماء football-data.co.uk مختصرة ("Man United"، "Sp Lisbon"). إذا نقص شعار فريق، أضف اسمه الكامل في `src/lib/data/team-aliases.ts` ثم شغّل `npm run logos:sync -- --retry`.

## إضافة مصدر أودز آخر

الكود منظم بحيث يسهل إضافة مصدر: كل ما يحتاجه `runDaily` هو قائمة `Fixture` (league، kickoff، home، away، odds). يمكنك كتابة ملف في `src/lib/data/` يجلب الأودز من The Odds API أو API-Football، ثم تمرّره بدل `fetchFixtures`. أسماء الفرق يجب أن تطابق أسماء football-data.co.uk (أضف جدول تحويل إذا اختلفت).
